# 离线调研采集系统

纯前端、零依赖（无需 npm install）的离线问卷采集演示应用。调查员可下载表单定义、
断网录入并保存草稿，恢复连接后同步到本地服务；支持字段级并发冲突人工合并与表单
版本升级后的字段映射迁移。

## 运行

```bash
node scripts/serve.mjs        # 默认 http://127.0.0.1:8088
# 或指定端口
node scripts/serve.mjs 9000
```

浏览器打开 `http://127.0.0.1:8088` 即可。也可用任意静态服务器指向本目录
（Service Worker 需要 http(s) 协议，不要用 file:// 直接打开）。

## 测试

```bash
npm test
# 等价于：
node --test tests/engine.test.js tests/storage.test.js
```

- `tests/engine.test.js`：条件显示、必填/选项/数值范围校验、答案差异、乐观锁同步计划、冲突合并、迁移映射（17 项）
- `tests/storage.test.js`：localStorage 桩下的完整链路——离线发件箱、断网刷新持久化、双设备冲突合并、v1→v2 迁移待处理（5 项）

## 功能与需求对照

| 需求 | 实现 |
| --- | --- |
| 下载表单定义、离线录入、保存草稿 | 顶栏「下载表单定义」缓存到设备库；草稿存于设备独立 localStorage 命名空间 |
| 离线刷新页面仍可用 | Service Worker 缓存应用外壳（`sw.js`）；断网开关与全部数据持久化在 localStorage |
| 恢复连接后同步 | 离线同步进入发件箱（角标计数），恢复网络自动同步，也可手动「同步发件箱」 |
| 必填 / 选项 / 数值范围 / 条件显示 | `js/engine.js` 的 `validateAnswers` 与 `isFieldVisible`；隐藏字段不参与必填校验 |
| 按样本编号查询采集时间、表单版本、修改记录 | 「采集记录查询」页搜索 + 详情页时间线（草稿历史与服务端修订历史均持久化） |
| 两台设备并发修改不静默覆盖 | 服务端记录带 `rev` 乐观锁；rev 落后且字段有差异时拒绝写入并返回冲突字段 |
| 人工选定字段版本、保留另一版历史 | 冲突弹窗逐字段选择本设备/服务端；合并条目保留双方完整快照（`merge.localSnapshot/remoteSnapshot`） |
| 表单升级后旧草稿字段映射迁移 | `js/forms.js` 的 `MIGRATIONS` 定义 v1→v2 映射（同名迁移、选项值转换、字段移除） |
| 无法对应的答案单独待处理 | 迁移产生 `pendingAnswers`，可「保留到备注 / 丢弃」，处理完才允许同步 |
| 样例数据与断网模拟 | 内置 3 条服务端记录（S-1001~S-1003）+ 1 份 v1 旧草稿（S-1004）；顶栏网络开关持久化；可一键重置 |

## 三个演示场景（页面内「演示场景与样例数据」页有引导）

1. **离线录入 → 断网刷新 → 恢复同步**：新建草稿 → 断开网络并刷新页面 → 同步入发件箱 → 恢复网络自动上传 → 记录查询。
2. **双设备并发冲突合并**：「一键模拟并发修改冲突」构造设备 A/B 基于同一 rev 的分叉修改，
   A 同步成功后 B 收到冲突弹窗，逐字段选择合并；详情页可查看保留的另一版快照。
3. **表单 v1→v2 迁移**：打开预置 v1 草稿 S-1004 → 迁移（满意度「非常满意」自动映射为「很满意」）→
   已移除的「其他说明」进入待处理 → 保留到备注并补齐新增必填项后同步。

## 目录结构

```
offline-survey/
├── index.html              # 单页外壳（顶栏、Tab、弹窗/Toast 容器）
├── sw.js                   # Service Worker：应用外壳离线缓存
├── css/styles.css
├── js/
│   ├── forms.js            # 表单定义 v1/v2、字段映射 MIGRATIONS（纯数据）
│   ├── engine.js           # 纯逻辑：条件显示、校验、差异、同步计划、迁移、合并（可单测）
│   ├── storage.js          # MockLocalServer（rev 乐观锁+历史）、DeviceStore、网络开关、种子数据
│   ├── app-core.js         # 应用状态与同步编排
│   ├── components.js       # 字段渲染、冲突/待处理弹窗、历史时间线、Toast
│   ├── views.js            # 草稿列表、表单编辑器、记录查询/详情、场景页
│   └── main.js             # 事件代理与渲染编排、SW 注册
├── tests/                  # node:test 单元与集成测试
└── scripts/serve.mjs       # 零依赖静态服务器
```

## 关键设计说明

- **乐观锁而非最后写入获胜**：每条服务端记录有单调递增 `rev`，草稿记录 `baseRev`。
  rev 不一致时再做字段级 diff——答案无差异仍允许快进，避免伪冲突；有差异才弹窗。
- **冲突合并可追溯**：人工合并生成 `conflict-merge` 历史条目，记录每个字段采用了哪一侧，
  并把两版完整答案快照一并存入历史，随时可审计。
- **迁移不丢数据**：字段移除或旧选项在新版本不存在时，答案不被静默丢弃，而是进入
  `pendingAnswers` 待人工处理，未处理完的草稿无法同步。
- **设备隔离**：设备 A/B 使用独立 localStorage 命名空间（`offline-survey:device:A:*` /
  `:B:*`），服务端数据在 `offline-survey:server:v1`，模拟两台真实设备与一个本地服务。
